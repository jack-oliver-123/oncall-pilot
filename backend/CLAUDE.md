# 后端开发约定

本目录存放后端服务、领域逻辑、数据访问和后端测试。

## 当前工具链

- 当前尚无后端 manifest、源码入口或可执行的服务命令；不得推断语言、框架、数据库或运行时。
- 首次引入后端工具链时，在同一 Change 中补充准确的安装、启动、静态检查、类型检查、测试、构建命令和入口文件。

## 工作范围

- 负责服务端接口、业务规则、数据持久化、后台任务和服务端测试。
- 对外接口、数据模型或业务行为发生变化时，必须回到根级 OpenSpec Change 进行追踪。

## 修改规则

- 遵守根目录 `CLAUDE.md` 中的 OpenSpec 组合工作流和阶段门禁。
- 先识别领域术语，并使用根级 `CONTEXT.md` 中的 canonical vocabulary。
- 通过清晰的模块接口隔离业务规则和基础设施适配器。
- 不要在 API 层静默吞掉错误；明确区分输入错误、业务拒绝和系统故障。
- 数据库、外部服务和配置变更必须记录影响范围及回滚策略。

## 验证重点

- 在提交前运行后端格式检查、静态检查、类型检查、测试和构建（如果项目已配置）。
- 覆盖正常流程、边界输入、权限失败、依赖失败和数据一致性场景。
- 接口行为变化时同步更新契约、测试和相关 OpenSpec artifact。
