# Domain docs

本仓库使用单上下文领域文档。engineering skills 探索代码库时，应按以下规则消费领域资料。

## 开始探索前读取

- 根目录的 `CONTEXT.md`（如果存在）。
- 根目录的 `docs/adr/` 中与当前工作区域相关的 ADR（如果存在）。

如果这些文件不存在，直接继续，不要先提示缺失或建议立即创建；当术语或决策真正确定时，再由 `/domain-modeling` 按需创建。

## 文件结构

```text
/
├── CONTEXT.md
├── docs/adr/
└── src/
```

## 使用 glossary 词汇

在 issue 标题、重构提案、假设或测试名称中命名领域概念时，使用 `CONTEXT.md` 定义的术语，不要擅自改用同义词。如果所需概念尚未记录，应将其视为领域词汇缺口，交给 `/domain-modeling` 处理。

## 标记 ADR 冲突

如果输出与现有 ADR 冲突，应明确指出，不要静默覆盖，例如：

> 与 ADR-0007 冲突，但值得重新审议，因为……
